## IMP-001 申請時の入力・エビデンス検証を標準化

- 対象: 申請内容とエビデンスを登録して申請 / 内容を修正して再申請
- 分類: 簡素化, 標準化, AI・ツール支援
- 効果: 高 / 実装工数: 中 / リスク: 低 / 確度: 高

**提案内容**: 初回申請と再申請に共通の入力ルール、必須項目、エビデンス要件、明確なエラーメッセージを定義し、送信前チェックを追加する。判断を要する経費妥当性は上長確認に残す。

**理由**: As-Isでは申請後に上長が内容とエビデンスの不備を確認し、不備時は差し戻しと再申請のループになる。申請時点で必須項目、形式、エビデンス有無を共通基準で確認すれば、後工程の手戻りを抑えられる。

**想定・推奨する機能 / サービス**
- 具体候補なし
- 理由: 現在のPower Appsアプリのデータ構造と実装方式が不明なため、具体機能を固定せず業務ルールの標準化を先行する。

**関連・依存する改善案**
- 組み合わせで効果向上: IMP-002 — 差し戻し理由の標準化と併用すると、予防ルールの継続改善に使える。

**未確認事項**
- 現行の差し戻し理由別件数と差し戻し率はどの程度か
- Power Appsアプリで実装可能な入力検証方式と改修権限は何か

## IMP-002 差し戻し理由と再申請ルールを標準化

- 対象: 社員へ差し戻し / 社員へ差し戻し / 内容を修正して再申請
- 分類: 簡素化, 統合, 標準化
- 効果: 中 / 実装工数: 低 / リスク: 低 / 確度: 高

**提案内容**: 差し戻し理由コード、具体的指摘、修正対象、再申請期限、再確認対象を共通様式にし、上長・部門長の差し戻し情報を一つの履歴として追跡する。再申請後も不備が残る場合の扱いは業務ルールとして別途決定する。

**理由**: 上長と部門長の双方に社員への差し戻しがあり、出力は同じ「差し戻し指摘」だが、理由分類、必須記載、再申請時の確認範囲が定義されていない。

**想定・推奨する機能 / サービス**
- 具体候補なし
- 理由: 差し戻し分類と再申請ルールの業務決定が先であり、記録先の製品選定は独立して行えるため。

**関連・依存する改善案**
- 組み合わせで効果向上: IMP-001, IMP-004 — 申請時予防と承認状態管理を強化する。

**未確認事項**
- 再申請後も不備または却下理由が解消しない場合の最大再申請回数とエスカレーション先は何か
- 部門長の却下は修正再申請を許す差し戻しのみか、申請終了となる却下も含むか

## IMP-003 5万円基準の承認要否判定を自動化

- 対象: 申請金額を確認
- 分類: 廃止, 標準化, 自動化
- 効果: 中 / 実装工数: 低 / リスク: 中 / 確度: 高

**提案内容**: 申請金額をシステムで50000円と比較し、5万円以上は部門長審査へ、未満は承認完了合流へ自動ルーティングする。閾値変更権限と変更履歴を統制する。

**理由**: As-Isでは上長が申請金額を確認した直後、固定閾値50000円で部門長承認要否を判定する。構造化された申請金額に対する決定的な判定であり、手作業確認を廃止できる可能性が高い。

**想定・推奨する機能 / サービス**
- 具体候補なし
- 理由: 現行アプリと後続承認基盤の接続方式が不明であり、業務上の自動判定を先に定義するため。

**未確認事項**
- 閾値変更の承認者と変更履歴の保管要件は何か
- 税・外貨換算・複数明細の場合に判定対象とする金額は何か

## IMP-004 承認状態・通知・滞留を一元管理

- 対象: 申請内容とエビデンスを確認 / 申請を審査 / 社員へ差し戻し / 社員へ差し戻し
- 分類: 標準化, 自動化, 維持
- 効果: 高 / 実装工数: 中 / リスク: 中 / 確度: 中

**提案内容**: 上長・部門長の人的判断は維持しつつ、依頼通知、担当、状態、判断日時、コメント、差し戻し履歴を一元管理する。期限超過時の通知・エスカレーションはSLA決定後に設定する。

**理由**: As-Isでは人による内容審査を維持する必要がある一方、承認依頼、結果、コメント、差し戻し、滞留の横断的な状態管理が明示されていない。担当間ハンドオフの見落としや追跡困難を防ぐ余地がある。

**想定・推奨する機能 / サービス**
- Power Automate: 承認アクションとクラウドフロー — 承認依頼、応答待ち、結果通知、状態更新を制御する（推奨候補 / 確度 中） [根拠: Power Automate での承認ワークフローを作成し、テストします, Power Automate の承認を始めましょう]

**関連・依存する改善案**
- 組み合わせで効果向上: IMP-002, IMP-003 — 差し戻し標準化と自動ルーティングで状態の一貫性が高まる。

**未確認事項**
- SLAと期限超過時の通知・エスカレーション経路は何か
- 代理承認、承認取消、再割当の許容ルールは何か
- Power Automate承認機能に必要なライセンスと環境権限を満たすか

## IMP-005 会計システムへの再入力を連携に置換

- 効果: 高 / 実装工数: 高 / リスク: 高 / 確度: 中

**提案内容**: 必要承認後の申請データを標準マッピングで会計システムへ連携し、手入力を廃止する。成功・失敗・失敗理由を申請単位で記録し、失敗時のみ経理担当者が原因確認、データ修正、再実行を行う。

**理由**: As-IsではPower Appsで登録済みの経費申請情報を経理担当者が会計システムへ再入力し、入力エラー時は修正して再登録する。重複入力とエラーループが明確に存在する。

- 具体候補なし
- 理由: 会計システム名、API・ファイル連携仕様、認証、ライセンスが未確認のため具体製品候補を示せない。

**未確認事項**
- 会計システムが提供するAPIまたは入出力ファイル仕様は何か
- 連携失敗時の再実行上限と経理担当者への通知方法は何か
- 自動登録後の取消・訂正処理はどの経路で行うか

## IMP-006 エビデンス保管を自動化し申請と関連付け

- 対象: エビデンスを所定の保管先へ保管
- 分類: 標準化, 自動化
- 効果: 中 / 実装工数: 中 / リスク: 中 / 確度: 中

**提案内容**: 必要承認後、エビデンスを所定の保管先へ自動保存し、申請ID、保存先、保存結果、版を記録する。失敗・重複・欠損時のみ経理担当者が是正して再実行する。

**理由**: エビデンスは申請時にPower Appsへ登録済みだが、承認後に経理担当者が別途所定の保管先へ保管している。手作業移送と申請との紐付け不備を削減できる。

**想定・推奨する機能 / サービス**
- Power Automate と SharePoint: SharePointコネクタによるライブラリへのファイル操作と変更トリガー — エビデンスを規定ライブラリへ保存し保存結果を追跡する（検討候補 / 確度 中） [根拠: Power Automate 用 Microsoft SharePoint コネクタ]

**未確認事項**

- 元ファイル、変換後ファイル、版のどれを保持対象とするか
- 保存失敗時の再実行と手動是正の責任者は誰か

## IMP-007 並行処理の完了・失敗・滞留を統制

- 対象: 会計システムへ経費情報を登録 / エラー内容を確認して修正 / エビデンスを所定の保管先へ保管 / 振込処理
- 分類: 標準化, 自動化
- 効果: 高 / 実装工数: 中 / リスク: 中 / 確度: 高

**提案内容**: 申請単位で会計登録とエビデンス保管の状態を管理し、両方成功時のみ振込可能とする。どちらかが失敗または期限超過の場合は担当者へ通知し、是正後に当該処理を再実行する。振込への迂回は許可しない。

**理由**: As-Isでは会計登録とエビデンス保管を並行実行し、両方の完了後に振込処理へ進む。一方、保管側の失敗経路、片側滞留、期限超過時の扱いが明示されていない。

**想定・推奨する機能 / サービス**
- 具体候補なし
- 理由: IMP-005とIMP-006の採否にかかわらず状態統制は成立するが、具体基盤は現在のデータストアと監視方式が未確認のため固定しない。

**未確認事項**
- 並行処理の期限超過判定に用いるSLAは何か
- 会計登録失敗と保管失敗の例外責任者は同一か
- 片側が長期停止した場合の申請取消または手動振込の許可ルールは何か
